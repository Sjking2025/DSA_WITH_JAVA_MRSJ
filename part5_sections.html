Section 04

The 40-Pattern Recognition Engine & Problem Protocol

Every interview problem is a combination of known mathematical invariants masked behind an unfamiliar narrative. Master the 14-step decomposition protocol and the 40 foundational algorithmic patterns.

The Mandatory 14-Step Problem-Solving Protocol

Step Phase Name Concrete Action Required
01Read & ExtractIdentify input types, output format, array constraints, and hidden assumptions (e.g. empty, negatives).
02Restate AloudExplain the problem in your own words in 30 seconds without reading verbatim from the screen.
03Brute ForceFormulate the simplest correct solution (usually exhaustive search or nested loops).
04Brute Force Big-OCalculate time and space complexity of the brute force solution (e.g. O(N²), O(2ⁿ)).
05Identify BottleneckLocate the precise operation that is wastefully expensive (e.g. repeated linear search in sub-array).
06Structural InsightDiscover the invariant, mathematical property, or monotonic behavior that enables pruning.
07Pattern MappingMatch the insight to one of the 40 recognized patterns (e.g. Sliding Window, Monotonic Stack).
08Data Structure ChoiceAnswer: "What minimal information must we maintain as we traverse?"
09Pseudocode / InvariantsDraft algorithm state transitions and loop invariants before touching the keyboard.
10Clean Java ImplementationWrite idiomatic Java 21 code with descriptive variable names and zero deprecated APIs.
11Dry Run with ExampleTrace state variables manually on a real sample input table line by line.
12Edge Case AuditTest null, single element, duplicates, negative values, boundary constraints, and 32-bit overflow.
13Recalculate Big-OProve the optimal time and auxiliary space bounds mathematically.
14Interview VerbalizationDeliver a concise 2-minute verbal summary of intuition, approach, trade-offs, and correctness.

Section 05

Learning Engines, Error Journal & Retention

True algorithmic capability is not measured by how many solutions you read. It is forged by how you diagnose failures, retain patterns across 60 days, and think when you are stuck.

The 7 Progressive Learning Modes

Mode 1: Full Teaching

Complete deep-dive: WHY, WHAT, HOW, visualization, brute force, bottleneck, and clean Java implementation.

Mode 2: Guided Inquiry

No code given. Only structural clues, invariant hints, and Socratic questions to prompt student derivation.

Mode 3: Mock Interview

The mentor plays a strict Tier-1 interviewer. Zero clues; asks follow-ups, introduces edge cases, challenges complexity.

Mode 4: Bug Lab Debugging

Given broken, subtle, or crashing Java code. Student must locate off-by-one, overflow, or logic bugs without IDE warnings.

Mode 5: Timed Assessment

Strict 35-minute countdown clock. No external tabs. Simulates real online assessment pressure.

Mode 6: Unseen Transfer

Novel problem with disguised pattern. Tests whether student can identify invariants without pattern labels.

Mode 7: Teach-Back

The student must verbally teach the problem and prove its correctness to the mentor. Ultimate test of mastery.

The D0 to D60 Spaced Repetition Engine

Viewing a solution is NOT mastery. Every problem follows a 7-checkpoint retention schedule: Day 0 (Initial Solve)  →  Day 1 (Independent Re-Code from Blank File)  →  Day 3 (Solve Variant Problem)  →  Day 7 (Verbalize Invariants Aloud)  →  Day 14 (Timed 25-Min Re-solve)  →  Day 30 (Solve Disguised Variation)  →  Day 60 (Permanent Active Recall Check).
